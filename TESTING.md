## Fixes found through testing

- Firebase room creation now checks the readable owner field and uses a rules-protected creation write; a transaction at the unreadable room root would fail.
- Firebase snapshots are normalised because Realtime Database removes empty arrays/objects.
- Replayed input IDs survive host checkpoint restoration.
- Local relay reconnect tokens are separate from public player IDs.
- The demo controller has reserved space on desktop, becomes inline on smaller screens and hides on final results, keeping host controls accessible.
- Map-bank questions are reserved for actual map controls, rather than appearing as text entry with the answer in the prompt.
- Robot Repair bonuses appear in the round cash ledger.
- Pause/resume adjusts memory reveal times as well as the activity deadline.
- The Firebase test runner includes a loopback-only proxy compatibility adapter. It leaves remote proxy routing unchanged and is not included in the web bundle. No installed dependency patch is needed to reproduce tests.
- The first GitHub browser run exposed a test waiting for the continuously moving money bag to become stationary. The test now uses the bag's keyboard control and selects a repeatable event sequence that always includes it.

## Reproduce

```sh
npm ci
npm run validate
npm test
npx playwright install --with-deps chromium
npm run test:e2e
npm run test:firebase  # Java 21+
npm run build
```

`docs/screenshots/` contains the start menu, TV question and phone controller captured from browser tests. Screenshots under `test-results/` and Playwright HTML reports are generated, ignored artifacts.

## Live multiplayer verification

The production site created a Firebase room, accepted an anonymous player in a separate 390×844 browser session, showed team membership and ready state, delivered a private answer and published results. Refreshing the phone restored its nickname and cash. Refreshing the host restored the room checkpoint and allowed the next round to start. No browser page errors were recorded. The temporary test room was removed afterward.

## Interactive update checks

Added engine coverage for automatic reveal only after every competitor answers, pause behaviour, selected difficulty, bounded tricks, shield protection and submission gating. The browser suite now exercises the pre-game difficulty dialog, a targeted trick on a second phone, clearing the trick, automatic results and the round-winner banner. The original ten-round, quick-match and reconnection suites remain enabled. Memory-only activities are removed from the playable menus and round flow.

The interactive update was verified on the public Pages URL with two independent Firebase phone sessions: difficulty choice, a targeted trick, clearing the trick, private answers and automatic winner reveal all passed. The 320-pixel difficulty dialog was checked for horizontal overflow. Live verification exposed a missing `target` field in the input rules; the bounded string field is now allowed, and emulator tests cover valid targets, malformed targets and spoofed writers. The updated rules were deployed to the production database.
